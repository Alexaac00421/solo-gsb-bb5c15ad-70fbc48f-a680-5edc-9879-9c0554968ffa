# 共享厨房过敏原交叉污染排程系统

Python (Flask) + SQLite 的 Web 应用：管理员录入待制作批次的过敏原集合、所用台面/器具、
预计时段与清洁记录，系统按**器具占用**与**清洁有效期**自动生成可执行顺序，
为每个批次标出风险来源；清洁缺失/失效/覆盖不足或时段冲突时**拒绝排入并保留阻塞原因**。
支持调整顺序后重新计算，并可导出排程与风险说明（CSV / JSON）。
器具检修期间不得安排生产：管理员可登记 / 修改 / 取消器具停用时段，
批次时段与有效停用时段相交即被阻塞，看板与实时导出反映最新停用状态。
批次配方过敏原可修订：每次修改必须填写变更原因与时间，系统保留前后集合的修订记录，
重新计算排程时使用最新集合，并在看板与导出的风险说明中标出最近一次变更。
管理员可把当前排程**发布为生产交接版**：发布时按现有规则重新计算，全部批次可排入时
才在同一事务内保存连续版本号与完整快照；看板同时显示实时排程与最新交接版，
按批次标出新增、移除及内容变化，历史版本不随后续数据修改变化，可随时查看与导出。
排程员还可**批量调整**：一次提交多个批次的新时段/器具与包含全部批次的目标顺序，
先试算整体影响（逐批对比调整前后状态、风险或阻塞原因），确认时若排程依据已变化
则拒绝过期方案，否则在同一事务内一次性保存全部调整。
对于因**清洁缺失、失效或覆盖不足**而受阻的批次，排程员还可做**清洁补救试算**：
选择受阻批次并输入清洁所需的正整数分钟数，系统逐台给出可连续执行清洁的最晚时窗，
再用虚拟清洁重算完整排程展示目标及其他批次的状态 / 原因变化；
试算全程不写入清洁记录、实时排程或交接版。

## 快速开始（Docker Compose，一键启动）

```bash
docker compose up --build
```

启动后访问：**http://localhost:8000**（页面页头也会显示访问地址与端口）。

首次启动会自动初始化 SQLite 并写入一组演示数据，覆盖以下情形，便于直接验证规则：

| 批次 | 结果 | 说明 |
| --- | --- | --- |
| 牛奶燕麦糊 → 花生能量棒（台面A） | ✅ 已排入（风险已缓解） | 切换前清洁覆盖 牛奶、麸质 且在有效期内 |
| 芝麻饼干（台面A） | ⛔ 已拒绝 | 残留 花生、大豆，现有清洁只覆盖花生，未覆盖全部残留源 |
| 贝类意面（台面B） | ⛔ 已拒绝 | 与已排入批次「清蒸鲈鱼」时段冲突 |
| 杏仁奶（搅拌机） | ⛔ 已拒绝 | 残留 牛奶，清洁有效期已过（清洁失效） |
| 烤箱（13:00–17:00 停用） | 🔧 停用检修 | 演示停用记录（加热管检修）；登记与之相交的批次即被阻塞，可在「器具与清洁」修改/取消 |

在看板上用 ↑↓ 调整顺序即自动重新计算；在「器具与清洁」补登清洁记录后点「重新计算」，
被阻塞的批次即可排入；在同一页面可登记 / 修改 / 取消器具停用检修时段，
批次时段与有效停用时段相交（端点相接不算相交）即被阻塞并标明器具与冲突时段。

## 本地运行（不用 Docker）

```bash
pip install -r requirements.txt
python app.py
# 访问 http://localhost:8000
```

## 配置项（环境变量）

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `8000` | 服务监听端口（Compose 中映射为 `8000:8000`，改端口需同步修改 `ports`） |
| `APP_URL` | `http://localhost:8000` | 页面展示的访问地址，反向代理/远程部署时设为外部地址 |
| `DB_PATH` | `<项目目录>/data/scheduler.db`（容器内 `/app/data/scheduler.db`） | SQLite 数据库文件路径 |
| `SECRET_KEY` | 开发默认值 | Flask session 密钥，生产环境请覆盖 |

Compose 中数据库通过命名卷 `scheduler-data` 持久化；删除数据可执行
`docker compose down -v` 后重新启动（会重新写入演示数据）。

## 排程规则

1. **器具占用**：同一台器具上，已排入批次的时段不得重叠；冲突批次被拒绝并记录冲突对象。
   器具处于**有效停用检修时段**时同样拒绝排入（见“器具停用检修”一节）。
2. **残留风险**：器具上前一批次留下的过敏原中，凡不在本批次配方内的即为交叉污染风险源。
3. **清洁要求**：存在风险源时，必须有一条清洁记录同时满足——
   - 清洁时间在前一批次结束之后、本批次开始之前；
   - 清洁有效期（有效至）不早于本批次开始时间；
   - 覆盖范围包含**全部**风险源（或标记为“全部过敏原”）。
   缺少清洁 / 清洁失效 / 覆盖不足时批次被阻塞，阻塞原因保留在看板与导出文件中。
4. **被阻塞批次**不占用器具、不产生残留；调整顺序或补登清洁后重新计算即可重新参与排程。

## 器具停用检修

1. 在「器具与清洁」页面的**器具停用检修登记**中选择器具、填写停用起止时间与
   **停用原因（必填）** 后登记。以下情形拒绝保存：器具不存在、原因缺失、
   起止时间无法解析或结束不晚于开始、与同一器具其他**有效**（未取消）停用时段重叠
   （端点相接不算重叠）。
2. 已登记的停用记录可**修改**（器具 / 起止 / 原因，校验规则同上）或**取消**；
   记录已取消后不能再修改，需重新登记。取消只是使该时段失效，记录本身保留，
   页面可查询全部记录及取消状态/取消时间。删除器具时其停用记录一并移除。
3. **排程判定**：批次使用任一器具的时段与该器具任一有效停用时段**相交**即阻塞，
   阻塞原因标明器具、停用时段与停用原因；端点相接（如批次开始恰为停用结束，
   或停用结束恰为批次开始）不算相交。受阻批次不占用器具、不产生残留，
   因此对后续批次的级联影响与其他阻塞原因一致。
4. 看板顶部展示当前全部**有效停用时段**；实时排程与 `/export.csv`、`/export.json`
   始终按最新停用状态计算（停用阻塞原因随批次导出，JSON 另含 `equipment_downtimes`）。
   停用记录另有 `/export/downtimes.csv` 与 `/export/downtimes.json`，含已取消记录与取消状态。
5. **发布交接版**：在现有发布事务内按最新停用状态与其他规则一起重新计算；
   有批次因停用（或其他原因）阻塞时拒绝发布、说明每个阻塞批次的原因且不生成版本；
   已发布的历史快照不随后续停用登记/修改/取消而变化。
6. 首次启动的演示数据中登记了一条「烤箱」停用（当天 13:00–17:00，加热管检修），
   可直接用于验证登记、修改、取消与导出；默认演示批次均不与该时段相交。

## 配方过敏原修订

1. 在「批次管理」每行的「修改过敏原」中调整集合，**必须填写变更原因与变更时间**；
   原因为空、时间缺失或集合无实际变化时拒绝保存。
2. 每次保存追加一条修订记录：受影响批次、修改前后集合、原因与操作者填写的时间，
   批次自身的顺序、器具关联与清洁记录均不受影响。
3. 重新计算排程一律使用最新过敏原集合；看板「风险来源与处置」列及导出文件中
   会标出该批次最近一次变更。
4. 删除批次后，其修订记录一并删除，不再出现在任何页面与导出中。

## 删除清洁记录（影响预演与留档）

1. 在「器具与清洁」点击清洁记录的「删除」，系统先**按当前排程预演**：
   列出因该记录失效而由“已排入（含风险已缓解）”变为阻塞的批次，
   包括原先由该清洁缓解的风险与删除后的阻塞原因；无影响时会明确提示。
2. 操作者**必须填写删除原因并确认**；取消或直接返回不改动任何数据。
   记录不存在或删除原因为空时拒绝操作，原数据保留。
3. 确认后在同一事务内删除记录，并保存**删除时间、删除原因、被删清洁快照
   （器具/时间/覆盖范围）与受影响批次快照**。
4. 删除后排程看板按**现有规则**重新计算（级联影响同样自然体现）；
   看板「清洁记录删除留档」面板可查询每次操作，导出文件（主导出 JSON，
   以及独立的删除记录 CSV / JSON）中同样可查，留档不随后续排程调整变化。

## 批量调整试算（多批次一次调整）

1. 在「批量调整」页面（导航栏或看板工具栏进入）为所选批次勾选「调整」并填写新的
   预计起止与所用器具，同时给出包含**全部现有批次**的目标顺序
   （批次 ID 逗号分隔，页面已按当前顺序预填，可直接改排）。
2. 点击「试算调整方案」：系统按当前器具占用、过敏原残留、清洁有效期与器具停用规则
   试算完整排程，逐批对比调整前后的时段、器具、状态、风险或阻塞原因，并汇总
   试算后的排入/阻塞数量。**试算不改动实时排程、导出与交接版**。
   以下情形拒绝试算且不产生任何写入：批次不存在、目标顺序缺失或重复、
   新时段无法解析或结束不晚于开始、所选器具不存在。
3. 在试算结果页点击「确认保存全部调整」：若试算后批次、器具、清洁、停用或配方等
   排程依据已发生变化，方案被判定**过期**并拒绝，需重新试算；否则在同一事务内
   一次性保存全部调整（任何失败都回滚，不会部分写入），实时排程随之更新。
   **含阻塞批次的方案允许保存**，但发布交接版仍按原规则要求全部批次可排入；
   已发布的交接版保持原样，不受调整影响。

## 清洁补救试算（补一条清洁能否解除阻塞）

1. 在「清洁补救试算」页面（导航栏、看板工具栏进入）只列出当前排程中因
   **清洁缺失 / 清洁失效 / 覆盖不足**而受阻的批次；选择一个目标批次并输入
   清洁所需的**正整数分钟数**后提交。以下情形拒绝试算且不产生任何写入：
   批次不存在、批次当前并非清洁类受阻（如仅因占用冲突或器具停用阻塞）、
   时长为空 / 非整数 / 小于等于 0。
2. **逐台时窗分析**：对目标使用的每台相关器具，系统取“**前一已排入批次结束 →
   目标批次开始**”的区间，按现有排入顺序扣除该器具的有效**停用检修时段**与
   **已排入批次占用**（端点相接不算相交）后，列出全部连续空闲段；从最晚的
   空闲段中找出能容纳所给时长的**最晚时窗**——清洁完成时间即时窗末端（作为
   建议清洁时间），有效期恰好覆盖目标开始；建议的单条清洁覆盖该器具上
   **全部新增残留过敏原**（不多选、不遗漏）。
3. **可解决 / 不可解判定**：任一相关器具区间内最长连续空闲段不足所给时长，
   或目标批次还存在占用冲突、器具停用等非清洁阻塞原因，或加入虚拟清洁重算后
   目标仍处于阻塞时，明确说明**不可仅靠清洁解决**（逐台给出原因、区间内阻挡
   时段与最长可用分钟数）；只有重算后目标批次可排入，才标注为可解决。
4. **虚拟清洁重算完整排程**：系统把建议清洁作为仅存在于本次试算的虚拟清洁，
   按现有顺序、占用、残留、清洁有效期与停用规则重算**全部批次**，展示目标及
   其他批次的状态 / 风险处置 / 阻塞原因变化（被解除的受阻批次可能改变后续
   批次的残留依据，级联影响自然体现）。
5. **试算不写入**：清洁记录、实时排程、导出与交接版在试算前后完全一致；
   试算页仅提供前往「器具与清洁」正式登记清洁的入口，登记后点「重新计算」
   实时排程才会变化。既有的清洁登记、删除预演留档、导出、交接版发布与
   启动方式保持不变。

## 生产交接版（发布 / 对比 / 历史快照）

1. **发布**：在排程看板或「交接版」页面点击「📦 发布交接版」。系统按当前
   器具占用、过敏原、清洁规则与**器具停用检修状态**重新计算排程：
   - 当前**没有任何批次**，或**存在阻塞批次**（含批次时段与有效停用时段相交）时，
     拒绝发布并说明原因（列出每个阻塞批次及其阻塞原因），不生成版本；
   - 全部批次均可排入时，在**同一事务**内保存：连续递增的版本号、发布时间，
     以及按顺序排列的每批次快照（批次、器具、时段、过敏原、风险来源、
     所用清洁、状态与最近一次配方变更说明）。
   - 计算与写入处于同一事务（写锁保护），并发修改或并发发布只会排在事务
     之前或之后，不会造成版本内容与判定依据不一致；版本号连续不重复。
2. **看板对比**：排程看板同时显示实时排程与最新交接版——
   实时排程表的「对比交接版」列标出**新增**（发布后才录入）与**有变化**
   （名称/过敏原/器具/时段/状态/顺序/风险来源与所用清洁的差异，逐项列出）；
   最新交接版面板标出**已移除**（发布后删除）与内容变化的批次。
3. **历史版本**：快照独立保存，之后修改或删除批次、器具、清洁记录，以及
   登记 / 修改 / 取消器具停用，均不影响已发布版本。「交接版」页面列出全部版本，每个版本可按发布时原样查看
   （`/releases/<版本号>`）并导出 CSV / JSON（`/releases/<版本号>.csv`、
   `/releases/<版本号>.json`）。
4. 实时排程与既有导出（`/export.csv`、`/export.json`）始终按**当前数据**
   重新计算，不受已发布版本影响；交接版导出则始终取自发布时快照。

## 页面与导出

- **排程看板** `/`：顺序、状态（已排入/已拒绝）、每批次风险来源与处置/阻塞原因，
  以及最近一次配方过敏原变更；顶部列出当前有效器具停用时段；↑↓ 调序、重新计算、导出、
  发布交接版；实时排程与最新交接版并排对比（新增/移除/内容变化）。
- **批次管理** `/batches`：录入/删除批次（过敏原、器具、预计时段），
  修改批次过敏原（需填写变更原因与时间）并查看全部修订记录。
- **批量调整** `/reschedule`：一次调整多个批次的预计起止与所用器具并给出目标顺序，
  先试算整体影响再确认保存；试算与确认分别为 `/reschedule/preview` 与
  `/reschedule/confirm`（见上节）。
- **清洁补救试算** `/cleaning-remedy`：选择清洁类受阻批次并输入正整数分钟数，
  逐台查看可连续清洁的最晚时窗并用虚拟清洁重算完整排程；
  试算提交为 `/cleaning-remedy/preview`，全程只读、不写入任何数据（见上节）。
- **器具与清洁** `/equipment`：维护台面器具与清洁记录（清洁时间、有效至、覆盖范围）；
  登记 / 修改 / 取消器具停用检修时段（同一器具有效时段不得重叠），查询全部停用记录及取消状态；
  删除清洁记录前先预演受影响批次，填写删除原因确认后留档（见上节）。
- **交接版** `/releases`：发布生产交接版、查看版本历史；`/releases/<版本号>`
  查看某版快照，`/releases/<版本号>.csv` / `.json` 按发布时原样导出。
- **导出**：`/export.csv`（Excel 友好，含 BOM）、`/export.json`（另含器具停用记录
  与清洁删除留档），均含排程顺序与每批次风险说明；器具停用记录另有
  `/export/downtimes.csv` 与 `/export/downtimes.json`（含已取消状态）；
  清洁删除记录另有
  `/export/cleaning-deletions.csv` 与 `/export/cleaning-deletions.json`。
